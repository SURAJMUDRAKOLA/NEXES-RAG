⚠️ Important update on Gemini free limits (Dec 2025 cut)
Google cut Gemini free tier by 50–92% in December 2025. text-embedding-004 is now 100 RPM and 1,000 RPD on free tier — NOT the 1500/min we planned on. This changes the embedding strategy. See the limits tab for the fix.
Every RAG operation → which API → why
1. Query classificationGROQ
Classify user query type (lookup/summarise/compare). Uses ~200 tokens. Fast, cheap, called once per query. Model: llama-3.1-8b-instant (fastest, 575 tok/s).
~200 tokens · llama-3.1-8b-instant · free
2. Query embeddingGEMINI
Convert user's question into a 768-dim vector for pgvector search. One call per query, ~50 tokens. text-embedding-004 is free at 100 RPM.
1 call · text-embedding-004 · free · 100 RPM cap
3. HyDE expansion (complex queries only)GROQ
Generate a hypothetical answer to embed instead of the raw query. Only fires for cross_doc/summarise types. ~300 tokens. Model: llama-3.1-8b-instant.
~300 tokens · conditional · llama-3.1-8b-instant
4. pgvector retrievalSUPABASE
Cosine similarity search via match_chunks() RPC. Runs inside Postgres. No external API call. Free forever. Uses the query embedding from step 2.
No API call · Supabase Postgres · always free
5. BM25 keyword searchSUPABASE
Full-text search via match_chunks_fts() RPC in Postgres. No API call. Runs in parallel with vector search. Free forever.
No API call · Supabase Postgres · always free
6. RerankingLOCAL — FLASHRANK
FlashRank ms-marco-MiniLM runs locally in Python. No API call at all. 20ms, 92MB model download once. Zero cost forever.
No API call · local CPU · 20ms · $0 forever
7. MMR diversificationLOCAL — PYTHON
Pure NumPy cosine similarity computation. No API call. 5ms. Runs on the embeddings already retrieved from pgvector.
No API call · NumPy · 5ms · $0 forever
8. Sufficiency checkGROQ
Ask LLM if retrieved context is enough to answer. ~400 tokens. Model: llama-3.1-8b-instant. Only fires if context might be insufficient — most simple lookups skip this.
~400 tokens · conditional · llama-3.1-8b-instant
9. Final answer generation ★GROQ
The main LLM call. Prompt = system + chunks (1000–2000 tokens) + history + query. Answer = 300–800 tokens streamed. Model: llama-3.3-70b-versatile. This is the biggest token consumer per query.
~2000 tokens in · ~500 tokens out · llama-3.3-70b-versatile
10. Related questions generationGROQ
Generate 3 suggested follow-up questions for the insights panel. ~300 tokens total. Model: llama-3.1-8b-instant. Optional — skip this to save tokens if needed.
~300 tokens · optional · llama-3.1-8b-instant
File ingestion — which API at each stage
Parse PDF / PPTX / DOCXLOCAL — PyMuPDF / python-pptx
Pure Python libraries. Zero API calls. PyMuPDF extracts text and images from PDFs. python-pptx extracts slides. python-docx extracts Word paragraphs. All run inside the Celery worker process.
No API · local CPU · $0
OCR (scanned PDFs only)LOCAL — PaddleOCR (lazy import)
Only triggers when PyMuPDF extracts zero text (scanned PDF). Lazy imported — only loads into RAM when needed. OpenCV preprocesses image first (deskew, denoise). All local, all free.
Lazy import · 800MB RAM when active · local only
⚠ Only load on scanned PDFs. Check: if len(extracted_text) < 50 → use OCR
Audio transcriptionGROQ — Whisper API
Groq offers whisper-large-v3-turbo via API. Send audio bytes → get transcript. No local model download. Free on Groq free tier. Much better than running faster-whisper locally (saves 500MB RAM).
groq.audio.transcriptions.create() · free tier · no local RAM
Image captioning (diagrams)GROQ — Vision model
For images embedded in documents: send image to Groq vision model to generate a text description. That description becomes the chunk content. Uses llama-3.2-11b-vision-preview on Groq.
~500 tokens per image · llama-3.2-11b-vision-preview · free tier
⚠ Only do this for images wider than 200px. Skip tiny icons/logos.
Contextual enrichment (per chunk)GROQ — Fast model
One LLM call per chunk to prepend context sentence. 100-token output per chunk. Batched in groups of 25 with asyncio.gather(). For a 50-page PDF (~120 chunks) = 120 Groq calls × ~150 tokens = 18,000 tokens total.
~150 tokens per chunk · llama-3.1-8b-instant · batched 25 at a time
⚠ This is your biggest Groq token consumer at ingest. A 50-page PDF ≈ 18K tokens. Watch daily limits.
Chunk embedding ★ most criticalGEMINI — text-embedding-004
Convert each chunk's enriched text into a 768-dim vector. Batched in groups of 50. For 120 chunks = 3 batch calls. This is where the Dec 2025 Gemini limit cut matters — 1000 RPD means ~1000 embed calls per day. Plan your ingestion accordingly.
Batched 50 at a time · text-embedding-004 · 100 RPM / 1000 RPD
Document summary generationGROQ — Fast model
After all chunks indexed: generate one summary per document (3-5 sentences). Uses first 8 chunks as input. ~800 tokens total. Stored in documents.summary column. Used for knowledge map and broad queries.
~800 tokens once per document · llama-3.1-8b-instant

The real bottleneck6000 tokens per minute
Each final answer uses ~2500 tokens. At 6000 TPM limit, you can fire one query every ~25 seconds. For a demo with one person chatting, this is fine — they type slower than that. For two people simultaneously, you might hit 429. The fix: tenacity retries automatically wait and retry.
Smart trickUse 8B model for cheap operations to protect 70B budget
llama-3.1-8b-instant has the same 6K TPM limit but uses tokens 10x faster. Use 8B for: classification (200 tok), sufficiency (400 tok), enrichment (150 tok × chunks), related questions (300 tok). Only use 70B for the final answer. This maximises the quality where it matters.

Critical insight1000 embed calls/day is the hard limit
A 50-page PDF produces ~120 chunks. Each chunk = 1 embed call (or batch of 50 = 1 call). So 120 chunks in 3 batch calls = 3 RPD units. You can index roughly 330 documents per day before hitting the limit. For a demo project indexing 5–20 documents total, this is a non-issue. The 1000 RPD resets daily at midnight Pacific time.
Fix if you hit limitsBatch size 50 + Redis cache = most embeds never hit API
With the Redis embedding cache (SHA-256 hash per chunk), re-indexing the same document costs zero Gemini calls. Re-asking the same query costs zero Gemini calls (same query embedding served from cache). In practice, Gemini embed calls are far fewer than raw chunk count suggests.

7 rules to guarantee zero billing, zero 429s, zero surprises
Follow all 7. They are ordered by importance — rule 1 matters most.
The 7 rules
RULE 1Never enable billing on Google Cloud / AI Studio
As long as billing is disabled on your Google Cloud project, you physically cannot be charged. If you accidentally exceed a limit, you get a 429 error — not a bill. Go to console.cloud.google.com → Billing → confirm the project linked to your AI Studio key has NO billing account attached.
RULE 2Groq has no billing — it is rate-limit only
Groq free tier has no credit card, no billing account, no pay-as-you-go. You literally cannot be charged. If you hit limits you get 429s, not charges. This is fundamentally different from OpenAI where going over free credit starts billing you.
RULE 3Always batch Gemini embed calls — never 1 chunk at a time
1 batch call of 50 chunks costs 1 RPD unit. 50 individual calls cost 50 RPD units. Your 1000 RPD limit goes 50× further with batching. Always use batch_embed(texts_list) — never a loop calling embed_single() per chunk.
batch_embed(texts) ← correct: 1 API call for 50 chunks for t in texts: embed_single(t) ← wrong: 50 API calls
RULE 4Cache query embeddings in Redis — same query = zero Gemini calls
A user often asks similar questions. "Summarise the report" and "Give me a summary" embed to nearly identical vectors. Cache the embedding keyed on SHA-256(query_text). TTL 1 hour. A cache hit means zero Gemini API call, zero latency on embed step.
KEY: embed:query:SHA256("what are the key findings") VALUE: [0.123, -0.456, ...] (768 floats, ~6KB JSON)
RULE 5Add slowapi rate limit — max 5 chat requests per minute per user
@limiter.limit("5/minute") on the /chat endpoint. This prevents: (a) a user accidentally spamming queries, (b) someone stress-testing your demo. At 5 queries/min, you use 5 × 3400 = 17,000 tokens/min — still under Groq's 6K TPM per-model limit per call.
RULE 6Cap document size at 50 pages for the demo
A 500-page PDF generates 1200+ chunks. Contextual enrichment = 1200 × 150 tokens = 180K tokens of Groq calls just for one document. Set MAX_PAGES_FOR_DEMO=50 in config. Show a clear error: "For this demo, files are limited to 50 pages." This keeps ingestion safely under limits.
RULE 7Make related questions generation optional (toggle in settings)
The related questions step (300 tokens per query) is a nice-to-have. When Groq token budget is running low, disable it. Add ENABLE_RELATED_QUESTIONS=true in config. One env var toggle. Saves 10% of daily Groq token budget at zero quality cost to the core RAG answer.
